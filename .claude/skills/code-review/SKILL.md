# コードレビュースキル

Next.js 15 + React 19 + Material UI v6 + Firebase を前提としたコードレビューの基準とチェックリスト。
PR レビュー・実装完了後のセルフレビュー時に本スキルを参照すること。

ルールの SSOT は [CLAUDE.md](../../../CLAUDE.md) と [feature-development スキル](../feature-development/SKILL.md)。

## 使用タイミング

- PR レビュー依頼時
- 実装完了後のセルフレビュー
- UI/UX レビュー
- パフォーマンスレビュー

---

## レビュー実施ルール（必須）

### 批判的視点の原則（最重要）

**レビューは批判的に行うこと。**

| 原則                   | 説明                                                   |
| ---------------------- | ------------------------------------------------------ |
| **問題を探す姿勢**     | 「問題がない」ではなく「問題を見つける」姿勢で臨む     |
| **仮定を疑う**         | 実装者の前提条件が正しいか検証する                     |
| **エッジケースを想定** | 正常系だけでなく異常系・境界値を重点的に確認           |
| **セキュリティ最優先** | XSS、認証漏れ、Firestore ルール不備がないか徹底調査    |
| **パフォーマンス懸念** | 不要な再レンダリング、購読リーク、依存配列の誤りを疑う |
| **ロジックの正しさ**   | 出席/欠席カウント、状態遷移、日付処理が仕様通りか検証  |

**禁止事項:**

- 「問題ありません」で終わらせない
- 表面的な確認で済ませない
- 実装者の意図を無条件に信用しない

### 複数観点でのレビュー

レビューは**異なる角度で最低 4 回**実施すること。各観点には専門サブエージェントを用意している。

| 回数   | 観点                         | サブエージェント                          |
| ------ | ---------------------------- | ----------------------------------------- |
| 1 回目 | 技術品質・命名規則           | `agents/tech-quality-reviewer.md`         |
| 2 回目 | セキュリティ・パフォーマンス | `agents/security-performance-reviewer.md` |
| 3 回目 | ユーザー視点（UX）           | `agents/user-perspective-reviewer.md`     |
| 4 回目 | ドキュメント整合性           | `agents/docs-consistency-reviewer.md`     |

規模の大きい変更では、サブエージェントを並列起動して観点ごとに分担させ、結果を統合する。
コンテキスト肥大化を防ぐため、各エージェントの返答は要約のみを受け取る。

## カテゴリ別チェックリスト

### 1. セキュリティ

| #   | 観点             | 確認内容                                                        | 重要度 |
| --- | ---------------- | --------------------------------------------------------------- | ------ |
| 1   | XSS 対策         | `dangerouslySetInnerHTML` を不用意に使っていないか              | 高     |
| 2   | 認証チェック     | 保護ページで `useAuth()` による未ログイン時リダイレクトがあるか | 高     |
| 3   | Firestore ルール | クライアントの権限チェックに依存せず、ルール側で守られる前提か  | 高     |
| 4   | データ越境       | 他ユーザーの `users/{uid}` 配下を読まない構造か                 | 高     |

### 2. パフォーマンス

| #   | 観点            | 確認内容                                                 | 重要度 |
| --- | --------------- | -------------------------------------------------------- | ------ |
| 1   | 再レンダリング  | `useMemo` / `useCallback` が適切に使われているか         | 高     |
| 2   | exhaustive-deps | `useEffect` の依存配列が正しいか                         | 高     |
| 3   | 購読リーク      | `onSnapshot` がクリーンアップで unsubscribe されているか | 高     |
| 4   | 無限ループ      | effect 内の状態更新 → 再レンダリングのループがないか     | 高     |
| 5   | バンドルサイズ  | 不要なライブラリ・重いインポートがないか                 | 中     |

### 3. 技術制約（必須遵守）

| #   | 観点        | 確認内容                                             | 重要度 |
| --- | ----------- | ---------------------------------------------------- | ------ |
| 1   | TypeScript  | `any` 型を使用していないか                           | 高     |
| 2   | ESLint      | lint 警告・エラーがないか                            | 高     |
| 3   | console.log | デバッグログが残っていないか                         | 高     |
| 4   | 命名規則    | コンポーネントは PascalCase、関数は camelCase か     | 中     |
| 5   | 共通 UI     | `src/components/` の共通コンポーネントを使っているか | 中     |

### 4. UI/UX

| #   | 観点         | 確認内容                                              | 重要度 |
| --- | ------------ | ----------------------------------------------------- | ------ |
| 1   | ローディング | `loading` 中に `LoadingScreen` を表示しているか       | 高     |
| 2   | エラー表示   | エラー時に `<Notice>` で理解できるメッセージを出すか  | 高     |
| 3   | 空状態       | データ 0 件時の表示が適切か（未登録／該当なしの区別） | 中     |

### 5. ロジックの正しさ

| #   | 観点               | 確認内容                                              | 重要度 |
| --- | ------------------ | ----------------------------------------------------- | ------ |
| 1   | 集計の正確性       | 出席/欠席回数・上限などの計算が仕様通りか             | 高     |
| 2   | 状態遷移の制御     | 退会済みなど、状態に応じた表示/操作制御がされているか | 高     |
| 3   | 日付処理           | dayjs / 祝日 / 年度（前期・後期）の扱いが正しいか     | 高     |
| 4   | データ整形の堅牢性 | 欠損フィールドに既定値を与え、壊れないか              | 高     |
| 5   | 条件分岐の網羅性   | 異常系・境界値（0 件・未設定）が考慮されているか      | 中     |

## レビュー実行コマンド

```bash
# Lint / 型チェック
npm run lint
npx tsc --noEmit

# console.log 残存チェック
grep -rn "console.log" --include="*.ts" --include="*.tsx" src/

# dangerouslySetInnerHTML 使用チェック
grep -rn "dangerouslySetInnerHTML" --include="*.tsx" src/

# any 型使用チェック
grep -rn ": any\|as any" --include="*.ts" --include="*.tsx" src/
```
